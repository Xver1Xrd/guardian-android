# Архитектура текущего этапа

`core:crypto` — независимый Kotlin/JVM модуль. `VaultCrypto` создаёт случайный DEK, выводит KEK через Argon2id, оборачивает DEK AES-GCM и шифрует записи с AAD. `VaultCodec` кодирует версии и строго ограничивает длины полей. Модуль не использует Android API, чтобы критические тесты запускались на JVM.

`app` — тонкий Android слой: Compose UI, короткая сессия и локальные файлы в `noBackupFilesDir`. Каждая заметка или логин хранится отдельным зашифрованным файлом с случайным UUID в имени. `AtomicFile` предотвращает частичную запись одного файла. В открытом виде остаются количество файлов, случайные ID и тип записи (`note`/`login`) в заголовке файла; поля заметки и логина шифруются. Поиск/сортировка после разблокировки выполняются в памяти. Список логинов не хранит пароль и TOTP URI; они загружаются при открытии записи.

Сейчас нет транзакций между несколькими файлами, глобального аутентифицированного индекса и защиты от удаления/отката целого набора файлов. Для 10 000 записей такой формат потребует индексирования и тестов производительности. Будущие модули и компоненты будут добавляться по мере реализации, без пустых интерфейсов.

`feature:generator` — отдельный Kotlin/JVM модуль: SecureRandom, равномерный выбор индекса, отбраковка целого кандидата для обязательного присутствия каждой выбранной группы символов. Словарные фразы и оценка стойкости пока не реализованы.

`feature:authenticator` — отдельное JVM ядро TOTP по RFC 6238: HMAC-SHA1/256/512, динамическая усечённая подпись и строгий импорт `otpauth://totp`. TOTP URI хранится внутри зашифрованной записи логина; экран записи рассчитывает код офлайн. Сканирование QR пока отсутствует.
